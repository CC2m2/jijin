# 基金净值估算 MVP 开发总结

## 1. 本次交付范围

本次迭代已将仓库从仅有 PRD 和技术方案文档的状态，落地为一个可运行的基金净值估算 MVP。

当前交付内容包括：

- 后端 API 服务，可完成持仓管理、基金信息查询、单基金估值、组合估值、历史净值趋势查询。
- 前端 Web 页面，可录入持仓、查看组合总览、查看估值明细、查看历史净值趋势。
- 本地 SQLite 数据存储。
- 基于天天基金（东方财富接口）的基金数据接入、缓存、降级与错误处理。
- MVP 级别的测试、构建与联调验证。

## 2. 代码结构变化

### 2.1 后端

新增 `backend/` 工程，核心结构如下：

- `backend/app/api/`：FastAPI 路由层。
- `backend/app/core/`：配置与统一异常。
- `backend/app/db/`：数据库引擎与会话。
- `backend/app/models/`：`positions`、`fund_snapshots` 数据模型。
- `backend/app/repositories/`：持仓 CRUD 访问层。
- `backend/app/schemas/`：请求与响应结构。
- `backend/app/services/`：基金数据服务与估值服务。
- `backend/tests/`：估值逻辑测试。

新增的后端能力包括：

- 健康检查接口 `GET /api/v1/health`
- 持仓管理接口 `GET/POST/PUT/DELETE /api/v1/positions`
- 基金信息接口 `GET /api/v1/funds/{fund_code}`
- 历史净值趋势接口 `GET /api/v1/funds/{fund_code}/history`
- 单基金估值接口 `POST /api/v1/valuation/fund`
- 组合估值接口 `GET /api/v1/valuation/portfolio`

### 2.2 前端

新增 `frontend/` 工程，核心结构如下：

- `frontend/src/App.tsx`：主页面，包含持仓管理、组合概览、估值明细、趋势面板。
- `frontend/src/api/`：Axios 客户端与接口调用封装。
- `frontend/src/components/PortfolioChart.tsx`：组合市值分布图。
- `frontend/src/components/FundTrendChart.tsx`：历史净值趋势图。
- `frontend/src/types/`：前端类型定义。

新增的前端能力包括：

- 持仓新增、编辑、删除。
- 组合总市值、总成本、总收益、总收益率展示。
- 估值明细与失败项展示。
- 历史净值趋势查看与刷新。

## 3. 数据与模型调整

本次 MVP 期间，对持仓模型进行了两次重要确认和扩展：

- 初始版本支持：基金代码、份额、成本单价。
- 后续增强版本增加：`position_date`，使不同日期的持仓成本可以独立保存。

当前持仓核心字段为：

- `fund_code`
- `fund_name`
- `position_date`
- `shares`
- `avg_cost`
- `created_at`
- `updated_at`

数据库存储位置：

- `backend/data/app.db`

为兼容已有 SQLite 数据，后端启动时增加了轻量 schema 自修复逻辑：

- 若 `positions` 表不存在 `position_date` 列，则自动补列。
- 历史数据自动以 `created_at` 日期或当天日期回填。

## 4. 数据源接入策略

基金数据接入统一由 `FundDataService` 负责，当前策略如下：

- 基金估值通过天天基金估算接口获取。
- 基金名称与类型通过基金代码列表接口补充。
- 历史净值趋势通过天天基金 F10 历史净值接口获取。

同时补充了以下能力：

- 内存 TTL 缓存，避免高频重复请求。
- 外部接口统一异常包装，返回业务可读的错误信息。
- 外部数据超时控制，超过配置时间后主动返回错误，不再无限等待。

## 5. 本次已解决的问题

### 5.1 持仓录入偶发失败

问题：新增或编辑持仓时，若外部基金名称查询失败，会导致接口行为不稳定。

处理：持仓保存不再强依赖外部基金名称查询。即使外部基金名称查询失败，也允许持仓先落库，`fund_name` 可为空。

### 5.2 持仓删除无效

问题：删除操作在前端表现为“没有反应”，实际原因是删除后的列表刷新与组合估值刷新耦合，导致界面反馈被阻塞。

处理：

- 删除交互改为更直接的内联确认。
- 删除成功后立即更新前端本地持仓列表。
- 组合估值改为异步刷新，不再阻塞删除完成反馈。

### 5.3 成本单价展示不满足需求

问题：持仓成本单价原先按金额格式展示，只有两位小数。

处理：统一改为展示四位小数，录入控件也同步支持四位精度。

### 5.4 成本与日期绑定

问题：原始持仓结构无法表达同一基金在不同日期对应不同成本价。

处理：增加 `position_date` 字段，前后端数据结构、接口和页面统一支持按日期保存持仓。

### 5.5 React/Ant Design 运行态告警

问题：前端使用 React 19，Ant Design v5 默认存在兼容告警。

处理：引入 `@ant-design/v5-patch-for-react-19` 兼容补丁并在前端入口加载。

### 5.6 趋势查询超时但前端拿不到明确错误信息

问题分为两层：

- 后端调用外部历史净值接口时，早期超时处理实现不完整。
- 前端对无 `response` 的超时错误提示不够清晰。

处理：

- 后端为天天基金查询增加超时控制与统一错误返回。
- 前端 Axios 拦截器增加对超时、无响应、后端错误消息三种场景的区分处理。

## 6. 前端交互与展示增强

本次在基础 MVP 之上，增加了以下交互增强：

- 持仓列表支持编辑、删除、趋势查看。
- 组合总览新增市值分布饼图。
- 单基金和组合项目支持查看趋势。
- 估值失败项在页面中保留错误信息，不会阻断其他基金展示。
- 趋势区域支持刷新。

## 7. 验证情况

本次迭代中已完成的验证包括：

- 后端 `pytest` 通过。
- 前端 `npm run build` 通过。
- 健康检查接口 `GET /api/v1/health` 可正常返回。
- 持仓新增、查询、删除接口已做实测。
- 基金查询、单基金估值、组合估值接口已做冒烟测试。

## 8. 当前已知边界

当前 MVP 仍存在如下边界，属于后续可继续增强项：

- 外部历史净值接口稳定性取决于天天基金与上游数据源。
- 历史趋势失败时目前主要通过消息提示反馈，尚未做更完整的页面级错误态。
- 数据库存储仍为本地 SQLite，适用于 MVP 与轻量单机场景。
- 未引入鉴权、多用户、多环境配置中心和生产级部署方案。

## 9. 本次交付结论

截至本次迭代结束，基金净值估算 MVP 已具备以下可用能力：

- 持仓录入与维护
- 单基金与组合估值
- 历史趋势查询
- 本地持久化存储
- 前后端联调可运行
- 常见异常路径已补齐错误处理与用户提示

本次开发先收敛至 MVP 可运行和核心体验可用，后续如继续推进，建议优先完善趋势失败态、后台运行稳定性和更细粒度的估值分析能力。
